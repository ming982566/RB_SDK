# RaceBear 第三方前端 AI 开发总入口

把本文交给能读取本地文件、编辑、构建和测试的 AI 编码工具，即可作为开发任务入口。
不依赖特定厂商的 Skill 安装方式。用户的实际需求、已有工程规则和执行权限优先；
本文指导完成已授权开发，不授予联网发布、操作真实电机或改写其它产品用户数据的权限。
本文用于开发第三方前端，不要求修改 SDK 内部实现。

授权边界：RGBAPP、`SEATBELT_CAN`、Haptic 和 Wind 的计算与输出完全不依赖 SDK 主授权。实现或审查
前端时，不能把 `RB_LicenseSnapshot.OutputAllowed` 作为 RGB/安全带/Haptic/Wind 页面的总开关；
该字段只控制 Motion、平台输出和其它受保护能力。未授权状态快照仍会
隐藏主运动专有计算结果，但 Haptic、Wind、RGB 和安全带产品状态可正常读取。

## 1. 可直接交给 AI 的任务

```text
读取 SDK 的 docs/RaceBearSDK_AI_DEVELOPMENT.md，并按其流程持续完成前端开发。
SDK 根目录：<SDK 解压目录>
应用目录：<目标项目目录>
产品名称：<产品名称>
目标范围：完整控制面板（或明确列出需要的页面）
语言与框架：沿用现有项目；新项目按本机可用工具链选择并记录理由
界面语言与风格：<需求；未指定时采用用户当前语言及适合控制面板的布局>
完成范围内的设计、代码、构建、离线功能验证、截图验收、部署包和使用文档。
每阶段更新开发记录，继续处理未完成项，不在只完成骨架或提交计划后结束。
没有设备的项目保留“硬件待验”，完成其它独立工作，不把模拟结果宣称为实机验证。
```

拿到任务后执行后续步骤，不要求用户再次批准普通的建文件、修复、构建或离线测试。
只在缺少影响实际实现的必要信息、需要用户持有的设备/凭据、执行环境拦截或存在破坏性
歧义时请求最小必要协助；等待期间继续完成不依赖该条件的工作。
用户只要求某个页面时按该范围交付，不自行扩大为全部 SDK 功能。

## 2. 阅读路线与事实来源

SDK 根目录通过 `include/RaceBearSDK.h` 与 `docs` 同时存在确定，不写死开发机绝对路径。
开始先检查项目已有代码、指令、Git 状态、SDK 包版本及产物，不覆盖未知改动。

| 顺序 | 文件 | 作用 |
|---|---|---|
| 1 | 本文 | 范围、开发阶段、记录、完成定义 |
| 2 | [页面与交互规范](RaceBearSDK_FRONTEND_UI_SPEC.md) | 页面、容器、控件、编辑及视觉标准 |
| 3 | [前端接入指南](RaceBearSDK_FRONTEND_GUIDE.md) 第 1-6 节 | 生命周期、配置所有权、状态和授权 |
| 4 | `include/RaceBearSDK.h` | 当前任务涉及的精确签名、类型、Size/Version、范围和返回值 |
| 5 | [API 手册](RaceBearSDK_API.md) 与接入指南对应章节 | 当前页面的参数、调用、限制、失败处理 |
| 6 | `tools/skills/racebear-frontend-panel/SKILL.md` | 可选工具无关规则入口；未安装 Skill 时也能直接读文件 |
| 按需 | [CAN 指南](RaceBearSDK_RB_CAN_GUIDE.md) | UID、绑定、健康、维护、恢复 |
| 按需 | [仪表开发](RaceBearSDK_DASHBOARD_DEVELOPMENT.md) | 包格式、设计器、像素、VOCORE、Web、资源 |
| 采用对象 ABI 时必读 | [统一对象 ABI](RaceBearSDK_OBJECT_API.md) / [同步服务目录](RaceBearSDK_SERVICE_API.md) | 协议第 0 节提供 key 分类、调用路线和公开服务域用途；第 2/5 节列对象/命令，服务目录列全部 265 项公开操作参数 |
| 按需 | SDK 根目录的 `examples/README.md` | 当前语言可复用的接入片段和可构建工程 |

Skill 的 feature-routing、integration-workflow、implementation-patterns、
validation-checklist 是实现时的索引与模板，位于
`tools/skills/racebear-frontend-panel/references`。
一次只展开本阶段需要的专题，功能完成前再用覆盖矩阵检查是否漏读。
不假设拥有 SimRacebear、SDK 私有源码、内部配置、硬件或内部 UI 适配层。

合同冲突先核对同包头文件与当前接口行为，记录问题并使文档或适配层一致；
不能凭函数名字猜参数，也不能把 README 中某个历史版本的“不公开”当成当前版本结论。
没有对应公开接口的能力明确标记限制，不伪造调用、默认值、参数意义或“已经支持”。

使用对象入口时先读 Describe 的实际目录；通用入口覆盖公开业务操作，旧导出仍保留。
服务包装只统一调用边界，不自动提供事务、异步完成或新的数据类；第一方操作非第三方合同。
高频遥测使用整帧 Binary，低频配置编辑处理版本冲突，异步动作保留
提交版本和任务归属。复杂 RGB/安全带只有二进制 schema，不能凭元数据猜字段或范围。
测试至少包含并发读取、冲突、短结果缓冲区不消费、不重复动作、满队列和退出时任务收敛。
使用同步服务时还须验签名/架构错误无副作用、浮点/句柄位模式、回调重入、缓冲区有效期，
并检查宿主导入表以证明调用确实通过对象 ABI。离线通过不等于已完成前端或硬件验收。

## 3. 起步检查与默认决策

建立项目自己的开发记录，例如 `docs/FRONTEND_DEVELOPMENT.md`、`docs/FRONTEND_VALIDATION.md`。
名称可沿用现有约定。记录中保留范围、决策、事实与下一步，避免堆积所有原始输出。

1. 核对目标 Windows 架构、编译器/运行时、UI 框架、JSON 解析器及其许可和离线可用性。
   SDK 包的常规第三方前端以 x64 为基线；直接链接示例按 VS2019/v142 验证。
   其它宿主语言按 C ABI 适配并验证布局；不要求安装与用户无关的新框架。
2. 把 SDK 根目录设为工程参数，按 Debug/Release 选择匹配的 DLL/LIB。
   记录 DLL 实际加载路径、运行时版本、头/LIB/DLL SHA256；不能只看文件名或时间。
3. 选择固定、独立的 AppDataName。SDK 自行初始化默认配置，不能从 SimRacebear 或
   其它客户复制配置与授权文件充当新产品默认值。
4. 先完成不连接硬件的最小初始化、状态、日志和关闭检查。首启失败先保留返回码、
   SDK 日志和实际目录/权限诊断；不要用猜测的沙箱原因修改全局 ACL 或安全策略。
5. 首次启动不自动触发真实输出、手动测试、回零或固件升级。之后的自动连接只能来自
   用户明确保存的设置及 SDK 许可，不能靠页面刷新隐式启用。

新项目未指定外观时采用任务导向的控制面板：清晰导航、密度适当的列表/表单、
可见的当前目标和状态、即时错误反馈。具体配色与框架由项目决定。
不要把 SDK API 名称直接堆成菜单或为每个函数生成按钮。

## 4. 开发覆盖矩阵

先从当前公开头提取 API 家族，再按 UI 规范映射到用户工作流。
建立以下矩阵；函数总数只用于检查 API 遗漏，不等于实现完成度：

| 功能/页面 | 用户操作与字段 | 公开接口与章节 | 容器/状态 | 前置依赖 | 实现状态 | 验证及证据 | 剩余限制 |
|---|---|---|---|---|---|---|---|
| 示例：输出 | 新增、编辑、保存、回读、连接断开 | RB_Output_* / 指南 13 | 目录+详情、连接状态 | 运行时/授权 | 未开始 | 未执行 | 无设备 |

完整控制面板应覆盖总览、授权、游戏/遥测、平台/手动测试、动态滤波、运动增强、
震动、风感、安全带、输出、安全带 CAN、CAN 设备与电机维护、RGB、仪表/VOCORE/Web、
系统设置、插件与日志诊断。按用户范围提供串口、自定义游戏/外部源、JSON/命令工具。
这些开发工具未纳入时记录“不在范围”，不能悄悄遗漏或声称覆盖全部公开能力。
兼容函数和辅助函数可以在服务层使用或注明替代接口，无需重复 UI。

每个实现项分别记录“未开始、设计完成、代码完成、构建通过、离线验证通过、
硬件待验/通过/失败、交付完成”。这些是不同维度，不以一个勾选框混淆。
尚待硬件的项保留该状态；功能“交付完成”表示已交付范围内文件，不表示硬件通过。
不存在的能力标记“SDK 不支持”，附公开合同依据及对用户工作流的影响。
所有日期使用真实日期，不填未来完成记录；没有执行的检查写“未执行”。

## 5. 按依赖持续开发

每个阶段都执行“读取对应合同 -> 更新矩阵 -> 实现 -> 构建 -> 针对性验证 ->
修复失败 -> 更新证据 -> 继续下一项”。阶段完成通常不需要另一次用户确认。
较大阶段拆成可验证的纵向工作流，不先铺满没有实现的空页面。

| 阶段 | 实现内容 | 通过条件 |
|---|---|---|
| A 环境与范围 | 工程、绑定、目录参数、范围矩阵、字段清单 | x64 架构与 ABI 验证，确定构建和部署路径 |
| B 基础运行 | 单 RuntimeOwner、状态总线、日志、主窗、授权、退出状态机 | 干净身份启动、无设备可用、关闭无残留；初始化失败也能显示诊断 |
| C 第一个配置闭环 | 一个简单配置页（例如风感）+ 独立草稿模型 | Read/编辑/Save/ReadBack 成功；Apply 依许可另测；中间输入与错误保留 |
| D 游戏与平台 | 游戏选择/安装配置、遥测、平台参数和受限预览 | 目录刷新稳定，选项变更不写错目标；无 Source 状态明确 |
| E 动感配置 | 动态多通道、运动增强多路由、震动、风感/安全带完整字段 | 独立配置域、候选目录、保留字段、边界输入和重新打开回读 |
| F 设备与输出 | 多实例输出、UID 绑定、健康/恢复、安全带 CAN、维护任务 | 先完成离线状态和互斥；真实连接与测试单列硬件验证 |
| G RGB 与仪表 | 灯带/图层/固件任务、内置/客户模板、VOCORE/Web | 资源与非空像素验证、最新帧管线、所有句柄关闭；无设备不冒充连接 |
| H 工具与完善 | 插件、系统、日志诊断及范围内开发工具 | 后台任务可收敛，失败可定位，配置与语言不互相覆盖 |
| I 产品与交付 | 逐页视觉、交互、语言、打包、使用及验证文档 | 验收矩阵逐项有证据，部署包可从干净目录启动，限制准确披露 |

后续阶段发现基础层问题时修复并重跑受影响用例，不为赶进度降低基线。
没有硬件不能阻止 A-E、离线表单、模拟异常、仪表渲染和大部分交付工作；
没有授权时配置与原始状态仍按合同实现，受保护运行态项目记录实际限制。

## 6. 架构与实现模板

推荐组织为五层，目录名按项目约定：

```text
native/bindings       C ABI、结构体和缓冲区；不含 UI 控件
runtime              单生命周期、状态快照、日志、受控任务和句柄
features             各配置域的目录/读写/回读与稳定身份解析
viewmodels           草稿、选择、错误、忙碌、可执行条件
ui                   导航、容器、表单、预览、语言与主题
```

SDK 调用不散落到控件绘制函数。C++ 使用可 join 的任务，C# 保留 callback delegate，
Python 保留 ctypes callback，Qt 回调排队至主线程；Web 前端使用受控本地桥，
不能让任意远程页面直接执行 native 命令。
精确模板与时序参见 Skill 的 `references/implementation-patterns.md`。

每个可编辑页具备以下可验证行为：

1. 从所属目录读取目标并按稳定身份定位。
2. 读取完整结构体，区分基线与草稿，按字段合同设置控件。
3. 编辑只改草稿；保留未显示/兼容字段及未提交的中间文本。
4. Save/Apply 前确认当前目标仍存在、读取已完成、草稿有效且没有冲突任务。
5. 用所属 API 提交并检查返回值；保存后回读并刷新业务字段。
6. 页面切换、语言切换、刷新、任务晚到均不能造成跨目标提交或丢草稿。
7. 所有测试有停止路径；页面离开停止本页测试，正常输出连接不随页面消失。

## 7. 验收矩阵

验收脚本可以使用宿主服务的替身、固定目录和故障注入模拟界面，不需要伪造 SDK DLL。
模拟模式与真实模式明显区分。真实 ABI、状态和持久化另用匹配 DLL 做集成验证。
有设备的项目只有在用户授权和具备现场条件时才运行。

| 类别 | 最低场景 | 证据与判定 |
|---|---|---|
| 构建/ABI | 目标配置构建；结构大小、偏移、数组、签名与回调 | 构建命令/退出码、绑定布局结果、二进制身份；语法检查不等于运行通过 |
| 干净首启 | 新产品身份、无硬件、无已复制的客户配置 | 默认目录与初始状态、日志、截图；失败保持可诊断 |
| 生命周期 | 初始化失败、启动失败、重复启动进程、正常关闭 | 清理已获得资源；每个进程初始化一次、退出无残留线程 |
| 目录 | A/B 切换、重排、删除当前项、刷新为空、热插拔 | stable ID 保持或明确不可用，写入始终对应当前确认目标 |
| 配置 | Read/Apply/Save/ReadBack、重启、默认值、未知字段 | 业务字段正确、其它字段不丢、保存与应用结果区分 |
| 编辑 | 清空、负号、小数、0、边界、溢出、非法粘贴、快速切换 | 不能逐键改回 1；错误不落盘；旧防抖任务不写新目标 |
| 任务 | 慢调用、重复点击、失败、页面关闭、结果晚到 | UI 响应、目标冻结、无 detach/悬空回调、错误阶段明确 |
| 授权 | 检查中、允许、锁定、恢复、网络失败 | 普通浏览/保存与复位可用；受保护操作按合同门控 |
| 游戏/遥测 | 无游戏、无数据、不支持输入、合法 0、断流 | 状态与值不混淆；Index 不当作行号或持久化键 |
| 平台/效果 | 支持的 DOF、多输入/路由、保护开关、各配置域切换 | 全字段往返，范围与单位正确，不添加宿主二次运动算法 |
| 输出/CAN | 多实例、多 UID、重复逻辑索引、断开/故障/恢复 | 所选与已绑定区分；前置条件、实际状态及错误可见 |
| 安全带保护 | 单左/单右/居中/双路、旧固件、上电回零、失联、急停、显式恢复 | 仅有效节点参与；无自动重使能/旧目标重放；断开后台等待；离线验证与实机释放分别记录 |
| 维护 | 导入非法/合法、未保存编辑、同步部分失败、目标离线 | 草稿及勾选不丢；不宣称自动回滚；任务未结束不退出维护 |
| RGB | 设备限制、逻辑段、RPM/ABS 双层、排序、Flash Save | 来源按效果目录、范围分层验证、主机/设备保存分开 |
| 仪表 | 内置/客户包、横竖尺寸、资源缺失、切包、输出独立开关 | 返回码、stride、非空像素和截图、句柄计数/关闭 |
| 串口/插件 | 回调注销、端口离线、刷新后索引变化 | 无跨线程控件调用、句柄配对，失败不自动无限重试 |
| 视觉/语言 | 全部页面、长译文、DPI、最小窗口、键盘 | 截图、控件可见及事件验证；无重叠/占位/假按钮 |
| 打包/升级 | 干净目录启动、缺依赖诊断、保留旧用户配置 | 发布文件表/哈希、实际加载路径、运行检查及已知限制 |

只重跑受本次修复影响的用例和必要的集成基线；不要用重复无关检查掩盖未完成项。
固件更新、回零和机械动作的成功不能由截图、mock 或函数返回 RB_OK 推断。

## 8. 交付文件

完成用户授权范围内的交付：

- 可维护源码、项目文件、依赖说明和可重复的构建命令。
- 正式运行目录或压缩包，包含宿主、匹配 DLL、实际必需的资源与运行依赖。
  LIB/公开头用于开发交付；只运行的用户无需收到开发缓存或私有 SDK 源码。
- `SDK_DEPENDENCIES` 或等价清单：SDK 版本、架构、配置、文件路径与 SHA256、
  第三方框架及运行库要求。
- 使用说明：首次启动、授权、选择游戏、配置平台/输出、保存应用、测试停止、
  设备维护、日志位置与故障排查；范围外功能无需写成可使用。
- 开发覆盖矩阵与验证报告：自动、视觉、人工、硬件检查分别记录。
- 已知限制与后续验收步骤：环境/授权/设备阻塞、尚未执行项目、具体复现条件。

部署以用户实际功能为准：VOCORE 需要 libusb，特定仪表需要 DashboardAssets；
游戏侧插件和功能插件只有获得可分发资源时才纳入包，缺失时提供诊断和获取路径，
不能把私有开发目录当成客户机器必然拥有的资源。
不要捆绑其它客户的配置、机器身份、激活信息、令牌、日志或授权文件。

默认完成本地构建与打包，不自动提交、推送、签名、上传或对外发布。
若用户已授权发布，再遵循所在项目的发布流程；不能把生成包称为已发布。

## 9. 持续执行、恢复与停止条件

每次进展更新说明已完成的用户工作流、验证结果和下一个具体缺口。开发记录保留：
当前目标、已接受的需求与技术选择、SDK 版本/路径、已修改文件、已通过验证、
未解决问题和下一步；恢复上下文后从第一项未完成工作继续，不重做已确认阶段。

不要因为首页能打开、编译通过、API 清单齐全或开发预算临近就标记整个项目完成。
对可解决的代码与构建错误持续修复；对相同外部阻塞不无限重试。
必要环境不可获得时记录具体错误、最小所需协助并继续独立工作。
用户要求停止/暂停时停止相应执行并保留状态，不擅自增加定时任务来继续。

最终报告至少包含：

```text
交付范围：
已实现且验证的工作流：
SDK 版本/配置与部署目录：
构建与测试证据：
运行方式与使用文档：
未实现、未验证与硬件待验：
需要用户完成的具体动作：
```

只有范围内的实现、构建、可执行离线验收、文件和说明均完成，且所有剩余项有真实状态，
才能报告“本地交付完成”。硬件或环境阻塞导致关键流程无法验证时报告
“实现完成，待验/受阻”，列出限制；不能报告未经验证的“完整实机交付”。

## 10. SDK 更新时的文档联动

SDK 维护方每次更新功能、行为、依赖或版本时，必须同时复核并更新受影响的：

- 本 AI 开发总入口与 `RaceBearSDK_FRONTEND_UI_SPEC.md`。
- `RaceBearSDK_FRONTEND_GUIDE.md`、`RaceBearSDK_API.md` 以及 CAN/仪表专题。
- `tools/skills/racebear-frontend-panel` 的完整入口、路由、实现模板和验证清单。
- README、相关示例、语言绑定及部署说明。

公开 ABI 不变不能免除复核：范围、单位、默认值、支持能力、授权、线程、保存应用、
错误处理或资源需求变化都可能影响 AI 生成的前端。按实际影响更新操作、字段、
容器/控件、阶段依赖和验收，不仅替换版本号。无影响项记录已复核及依据。

开发阶段同步已有文档分发副本及其引用依赖；正式发布阶段同步公开 SDK 包，并核对
打包复制项、允许清单、文件一致性和最终 ZIP 中的文档/完整 Skill。
未完成当前阶段的文档联动不能报告完整 SDK 交付；发布仍需用户授权。

第三方前端升级 SDK 时，从同一发行包更新文档、Skill、头与匹配产物，
对照变更重新检查功能覆盖矩阵和受影响验收用例。不要继续用旧 Skill 的参数范围、
功能限制或线程假设驱动新版 SDK；未能验证的兼容性明确记录。
